## 2. ポート早見表

| ポート | 場所 | ピン | 何を繋ぐか |
|---|---|---|---|
| **PORT.A**（赤） | 本体上部 | G32 = SDA / G33 = SCL | ENV Ⅲ（**I2C バス0**） |

| LED バー | ベース内部 | **G25** | 配線不要 |

**使えないピン**: GPIO16 / GPIO17（PSRAM が占有）

## 3. HO-1　Lチカ

### 配線

**ありません。** USB ケーブルで PC と繋ぐだけです。

→ **図0** を参照

### 押さえる点

LED バーはベース側面に内蔵されていて、データ線は **G25** です。PORT.A や PORT.B とは競合しません。

**明るさは 0〜100 のパーセント指定で、12% 程度で十分です。** 白（`0xffffff`）で 10 個を 100% 点灯すると約 600mA になり、Core2 の入力仕様（5V @ 500mA）を超えます。

```python
rgb25 = RGB(io=25, n=10, type="SK6812")
rgb25.set_brightness(12)
```

## 4. HO-2　温湿度センサー

### 配線

```
Core2 PORT.A ──Groveケーブル──→ ENV Ⅲ Unit
（本体上部・赤）
```

Grove ケーブルを挿すだけです。向きは物理的に決まっているので、間違えようがありません。

| 線の色 | 信号 | Core2 PORT.A | ENV Ⅲ |
|---|---|---|---|
| 黒 | GND | GND | GND |
| 赤 | 5V | 5V | 5V |
| **黄** | **SDA** | **G32** | **SDA** |
| **白** | **SCL** | **G33** | **SCL** |

両者の割り当ては一致しているので、そのまま繋がります。

> **他社の Grove センサーを繋ぐ場合は注意が必要です。** M5Stack の HY2.0-4P は、Seeed 社の本家 Grove 規格とは I2C のピン順が逆です（本家は 黄=SCL、M5Stack は 黄=SDA）。コネクターの形状は同じなので物理的には挿さりますが、信号が入れ替わります。

→ **図1** を参照

### 確認方法

```python
i2c = I2C(0, scl=Pin(33), sda=Pin(32), freq=100000)
print([hex(a) for a in i2c.scan()])
```

- `0x44` = SHT30（温湿度）
- `0x70` = QMP6988（気圧）

**`[]` が返ったら PORT.B に挿していないか確認してください。**

## 5. HO-3　サーボ

**ここだけ配線が複雑です。** ブレッドボードは運営が事前に組み立てて配ります。

### 配線

```
                   ┌──────── ブレッドボード（組立済） ────────┐
USB ACアダプター ────┼─ ＋5V ─┬──────────────────────────────┼→ サーボ 赤
                   │        │                              │
                   │   電解コンデンサー 1000µF                │
                   │        │                              │
Core2 PORT.B ──────┼─ 330Ω ─┼──────────────────────────────┼→ サーボ 橙（信号）
  白 (G26)       │        │                              │
Core2 PORT.B ──────┼─ GND ──┴──────────────────────────────┼→ サーボ 茶
  黒 (GND)       │                                        │
                   └────────────────────────────────────────┘
```

→ **図2** を参照

### 使う線は2本だけ

変換ケーブルは、**黒（GND）と信号線の2本だけ**を使います。赤（5V）と未使用の線は、運営が事前に根元で切断・絶縁しておきます。

| 線 | 用途 |
|---|---|
| **黒** | GND → ブレッドボードの −レール |
| **信号線** | G26 → 330Ω → サーボの橙 |
| 赤 | **切断済み**（繋ぐと再起動します） |
| もう1本 | **切断済み**（G36 は入力専用で使えません） |

> **信号線の色は、変換ケーブルの製品によって異なります。** 今回使用しているケーブルでは **白** が G26 でした。公式ドキュメントでは PORT.B の黄が G26 ですが、変換ケーブル内部で入れ替わっている製品があります。
>
> **配布前に1本テスターで実測し、信号線を特定してください。**（手順は §9 を参照）

### 参加者がやること（2手のみ）

1. サーボの3ピンをブレッドボードのヘッダーに挿す（**橙 赤 茶** の並び）
2. Grove 変換ケーブルを **PORT.B** に挿す

**通電は最後**です。配線を済ませてから AC アダプターをコンセントに挿します。

### 絶対に守ること

| | 理由 |
|---|---|
| **使うのは黒と白の2本だけ** | 赤を繋ぐと外部電源とM5Stackの5Vが衝突し、再起動する |
| **GND は必ず共通にする** | 基準電位が定まらず、サーボが暴れる |
| ホーンには紙の指示針だけ | 指を挟む・机から落ちる事故を防ぐ |

**赤（5V）と黄（G36・未使用）は、運営が事前に根元で切断し熱収縮チューブで絶縁**しておきます。手元に残るのは黒と白の2本だけになり、挿し間違えようがなくなります。

## 6. HO-4 / HO-5　ブラウザー連携とAI

### 配線

HO-2 と HO-3 の配線を**同時に**行います。追加の部品はありません。

```
PC ──USB──→ Core2 ──PORT.A──→ ENV Ⅲ
                    └─PORT.B──→ ブレッドボード ──→ サーボ
                                      ↑
                              USB ACアダプター
```

→ **図3** を参照

**PORT.A と PORT.B は別系統なので、Grove ハブは不要です。**

### HO-5 で追加するもの

**ありません。** 配線は HO-4 のまま、ブラウザー側のコードだけが変わります。

### 通信の約束

```
ボード → PC:  {"t":25.3,"h":48.1,"btn":0}
PC → ボード:  {"servo":120,"status":"HUMID","msg":"換気しましょう"}
```

### 注意

**IDE とブラウザーページは同時に接続できません。** シリアルポートは1つのアプリしか掴めないため、IDE の「Disconnect」を押してからページの「接続」を押します。

## 7. HO-6　Pan-Tilt（運営デモ / 3日版のみ）

### 配線（Grove ハブは使いません）

**ENV Ⅲ と Pan-Tilt を、別々のポートに独立して繋ぎます。**

```
Core2 PORT.A ──Groveケーブル──→ ENV Ⅲ           … I2C バス0
（赤・本体上部）  G32=SDA / G33=SCL

Core2 PORT.C ──Groveケーブル──→ Pan-Tilt 制御基板 … I2C バス1
（青・ベース側面） G14=SDA / G13=SCL    ※赤線は使わない
                                          │
          USB ACアダプター ── 4.8〜5V ───────┘  ← サーボ電源
               GND は Grove の黒線経由で Core2 と共通
```

→ **図5** を参照

### なぜ2つのポートに分けられるのか

ESP32 には **I2C コントローラが2系統**あります。`I2C(0)` と `I2C(1)` を別々のピンに割り当てれば、2本の独立したバスとして同時に使えます。

```python
i2c_env = I2C(0, scl=Pin(33), sda=Pin(32), freq=100000)   # PORT.A
i2c_pca = I2C(1, scl=Pin(13), sda=Pin(14), freq=100000)   # PORT.C
```

**PORT.B は I2C に使えません。** G36 が入力専用ピンで、双方向通信が必要な SDA を割り当てられないためです。したがって2つ目の I2C は PORT.C 一択になります。

### バスを分ける利点

**0x70 のアドレス衝突が原理的に起きなくなります。**

| デバイス | アドレス | バス |
|---|---|---|
| SHT30（温湿度） | 0x44 | バス0 |
| QMP6988（気圧） | **0x70** | バス0 |
| PCA9685 | 0x40 | バス1 |
| PCA9685 の All Call | **0x70** | バス1 |

同じ 0x70 が2つありますが、**別のバスなので出会いません。** 「同じ番地の家が2軒あっても、通りが違えば郵便は届く」ということです。

ALLCALL の無効化は、この構成では必須ではありません。ただし将来このバスに別のデバイスを足す可能性と、`scan()` の結果が紛らわしくなるのを避けるため、コードには残してあります。

### 3つのポートを同時に使える

| ポート | 用途 |
|---|---|
| PORT.A | ENV Ⅲ（温湿度） |
| PORT.B | SG92R（1軸サーボ・HO-3） |
| PORT.C | Pan-Tilt（2軸サーボ） |

互いに干渉しないので、**全部同時に動かせます。**

### 繋ぐ前に必ず測ること

**PORT.C に繋ぐ前に、Pan-Tilt 基板側の SDA / SCL のアイドル電圧をテスターで測定してください。**

| 実測値 | 対応 |
|---|---|
| 3.3V | そのまま繋いでよい |
| 5V | **I2Cレベルシフターが必須**（ESP32 は5Vトレラントではない） |

判断に迷うなら、最初からレベルシフターを入れるのが安全です。

> **PORT.C に5Vのバスを直結すると、Core2 の I2C が壊れる可能性があります。** バス0（PORT.A）まで巻き添えになると、センサーも読めなくなります。順番を守ってください。

### PORT.C のピン割り当ては実機で確認

図とコードでは **黄 = G14 = SDA、白 = G13 = SCL** としています。これは M5Stack 公式のピンマップどおりです。

ただし Pan-Tilt 基板側のコネクター結線までは保証できないため、`scan()` に何も出ない場合は入れ替えて試してください。

```python
# 逆だった場合
i2c_pca = I2C(1, scl=Pin(14), sda=Pin(13), freq=100000)
```

### コード側で必ずやること

```python
pca.set_freq(50)       # ★初期状態は50Hzではない★
```

### 可動範囲のリミット

ブラケットの構造上、180度全域は回りません。**範囲外の指令を出し続けるとギヤが傷みます。**

```python
PAN_LIMIT  = (30, 150)     # 実機で確認した値に
TILT_LIMIT = (70, 130)
```

### 付属カメラについて

Pan-Tilt キットのカメラは **Raspberry Pi の CSI 接続用**で、Core2 では使えません。画像を扱いたい場合は PC の Web カメラと Prompt API のマルチモーダル入力を使ってください。

## 9. トラブル時の切り分け

| 症状 | 第一容疑 |
|---|---|
| ボードが認識されない | ケーブルが充電専用 / IDE が繋ぎっぱなし |
| LED が光らない | `set_brightness()` が 0 になっていないか |
| 本体が熱い | 明るさを上げすぎ。12% に戻す |
| `i2c.scan()` が `[]` | PORT.B に挿している |
| **サーボで再起動する** | **切断したはずの赤線が繋がっている** |
| **サーボが無反応（電源は正常）** | **信号線の色が想定と違う。テスターで実測する** |
| **サーボが暴れる** | **共通 GND が繋がっていない** |
| サーボが無反応 | AC アダプター未通電 / 信号が G36 側 |
| サーボが唸る | 可動範囲超過。すぐ止めて校正 |
| 画面が真っ黒 | `page0.screen_load()` を呼んでいない |
| 日本語が □ | `lv.AlibabaSans_JP24` 以外を指定している |
| Pan-Tilt が動かない | `set_freq(50)` を呼んでいない |

### 変換ケーブルの信号線を特定する

ケーブルを PORT.B に挿し、WebTerminal で以下を実行します。

```python
from machine import Pin, PWM
s = PWM(Pin(26), freq=50)
s.duty_ns(10000000)      # デューティ比 50%
```

テスターの黒プローブを**ケーブルの黒線**、赤プローブを他の線に当てます。

| 測定値 | 判断 |
|---|---|
| **約 1.65V** | **その線が G26（信号線）** |
| 0V 付近 | 違う線 |

さらに確実を期すなら、デューティ比を変えて比例することを確認します。

```python
s.duty_ns(2000000)     # 10% → 約 0.33V
s.duty_ns(18000000)    # 90% → 約 3.0V
```

**電圧が比例して変化すれば、その線が信号線で確定です。**
| バス1に何も出ない | PORT.C の SDA/SCL が逆。Pin(13)/Pin(14) を交換 |
| バス1で ETIMEDOUT | プルアップ不足、またはレベルシフターが必要 |
| **バス0まで壊れた** | **PORT.C に5Vバスを直結した可能性。要テスター確認** |
