# ブラウザー内AI × マイコン ハンズオン

**ブラウザーの中で動くAI**（Chrome の Prompt API / Gemini Nano）と、**マイコンボード**（M5Stack Core2 for AWS）を組み合わせる、2日間のインターンシップ用教材です。

温湿度センサーの値を読み、AI が状況を判断し、その結果でサーボモーターが動く。この一連の流れを自分の手で繋ぎます。**推論は端末の中で完結するので、ネットワークを切っても動きます。**

```
センサー ──→ マイコン ──USB──→ ブラウザー ──→ Gemini Nano
                 ↑                              │
                 └──────── 制御コマンド ─────────┘
```

---

## はじめかた

**インストールは不要です。** 下のURLを Chrome で開くだけで始められます。

```
https://masaog.github.io/m5ai/
```

うまく動かないときは、まず診断ページを開いてください。

```
https://masaog.github.io/m5ai/check.html
```

## 必要なもの

### PC

| 項目 | 要件 |
|---|---|
| ブラウザー | **Google Chrome 148 以上**（公式ビルド） |
| OS | Windows / macOS / Linux / Chromebook Plus |
| メモリ | 16GB 以上 |
| 空きストレージ | 22GB 以上 |

対応しているのはデスクトップ版の Chrome だけです。モバイルや iOS では動きません。Edge や Brave などの Chromium 系ブラウザーも対象外です。

### AI モデルの事前ダウンロード（必須）

初回利用時に AI モデル（約4GB）がダウンロードされます。**演習の前に必ず済ませておいてください。**

参加者の方は、専用ページでボタンを1つ押すだけです。

```
https://masaog.github.io/m5ai/setup.html
```

このページに手順と注意点がすべて載っています。**随時更新されるので、案内メールより優先してください。**

運営・メンターの方は `check.html` のセクション2からも操作できます。

> **Chrome やモデルの更新後、`downloadable` に戻ることがあります。** 一度済ませていても、演習の直前にもう一度確認してください。

## 画面上でできること

**Day2 の開発では、ファイルを編集しなくてもかなりのことができます。**「AI の設定」の各タブで、以下を書き換えて「設定を反映」を押すだけです。

| タブ | 書き換えるもの |
|---|---|
| システムプロンプト | AI の役割 |
| 出力スキーマ | AI に返させる JSON の形 |
| ロジック | いつ AI を呼ぶか / 出力をボードにどう渡すか |
| 表示 | ブラウザー画面に何をどう出すか（HTML） |
| パラメーター | temperature、topK、制約の有無 |

例えばシステムプロンプトを書き換えるだけで、**コードを1行も変えずに**まったく別のアプリになります。

```
あなたは観葉植物の世話係です。土の乾き具合を温湿度から推測し、
水やりの緊急度を servo 0〜180 で表してください。
```

> リロードすると初期値に戻ります。気に入った設定はメモに残してください。

## 試してほしいこと

**1. 機内モードにする**

ネットワークを切っても推論が動きます。これがオンデバイスAIです。

**2. スキーマ制約を外す**

「パラメーター」タブの「スキーマ制約を外す」にチェックを入れて推論すると、`JSON.parse` が失敗します。AI が「はい、承知しました…」のような文章を返してくるためです。

これが `responseConstraint` を使う理由です。**ハードウェアを動かすときは必須**と考えてください。

**3. AI を呼ぶ頻度を変える**

推論は端末の CPU / GPU を使います。「毎回（1秒ごと）」にすると PC が重くなるのが体感できます。**「いつ呼ぶか」を設計するのが、このハンズオンで一番実務的な学びです。**

## ポート早見表

| ポート | 場所 | ピン | 用途 |
|---|---|---|---|
| PORT.A（赤） | 本体上部 | G32 = SDA / G33 = SCL | ENV Ⅲ（I2C バス0） |
| PORT.B（黒） | ベース側面 | **G26** / G36（入力専用） | サーボの PWM 信号 |
| PORT.C（青） | ベース側面 | G14 = SDA / G13 = SCL | Pan-Tilt（I2C バス1） |
| LED バー | ベース内部 | **G25** | 配線不要 |

**GPIO16 / GPIO17 は使えません**（PSRAM が占有しています）。

## つまずいたら

| 症状 | 確認すること |
|---|---|
| `LanguageModel is not defined` | Chrome のバージョン。`file://` で開いていないか |
| Gemini Nano が利用不可 | メモリ 16GB 以上か |
| ポートが選べない | **IDE を Disconnect したか**（最頻出） |
| 接続直後にボードが再起動 | `app.js` の `setSignals` |
| 数値が出ない | IDE のターミナルで `{"t":...}` が流れているか |
| **サーボで再起動する** | **Grove の赤線がブレッドボードに刺さっている** |
| **サーボが暴れる** | **共通 GND が繋がっていない** |
| 画面が真っ黒 | `page0.screen_load()` を呼んだか |
| 日本語が □ になる | `lv.AlibabaSans_JP24` を使っているか |
| AI が JSON を返さない | `responseConstraint` を渡しているか |

ログの「生データも表示」にチェックを入れると、ボードから届いた行がそのまま見えます。切り分けに使ってください。

## 設計方針

このコードを読む・改造する方向けに、意図を書いておきます。

**外部リソースを一切読み込みません。** CDN もフォントも使っていません。機内モードでの動作デモが成立しなくなるためです。追記する際も、この方針を守ってください。

**ビルドツールを使いません。** npm も webpack も不要で、ファイルをそのまま置けば動きます。演習時間が短いため、環境構築で時間を失わない構成にしています。

**`localStorage` を使いません。** 設定はリロードで消えます。参加者が前回の状態に引きずられないようにするためです。

**通信は USB（Web Serial）のみです。** Prompt API は https か localhost でしか動かず、https のページから `http://192.168.x.x` を叩くと混在コンテンツでブロックされます。ボード自身をサーバーにするとページがセキュアコンテキストでなくなります。**USB が唯一素直に成立する経路**です。

## 技術的な前提

- [Prompt API](https://developer.chrome.com/docs/ai/prompt-api) — Chrome 148 でフラグ不要になりました
- [Web Serial API](https://developer.chrome.com/docs/capabilities/serial) — ユーザー操作からのみポートを開けます
- [UIFlow2](https://uiflow2.m5stack.com/) — ボード側の開発環境。ブラウザーで動きます

ボード側は MicroPython です。UIFlow2 のブロックで組んでから、生成された Python を読む流れを想定しています。
